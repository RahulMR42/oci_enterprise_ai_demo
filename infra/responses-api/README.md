# Responses API Terraform

This module owns the deployment contract for the live Responses API demo.

## Resources

- The Responses API demo uses the OCI-hosted on-demand `openai.gpt-oss-120b` model.
- No dedicated AI cluster or model endpoint is required for this demo.
- The six-character resource suffix is generated by Terraform using `terraform_data.resource_suffix`, so the value is stable across refreshes and normal applies as long as Terraform state and `.resource_suffix` are preserved.
- The OCI Generative AI project is created by Terraform through the OCI CLI because the local Terraform provider set does not expose a native project resource in this workspace.
- Any future OCI resources required by this demo must be added to this module before the runtime code depends on them.

The OCI Generative AI project OCID and API key secret are runtime settings for the OpenAI-compatible endpoint. Do not commit API key secrets.

## Usage

```bash
terraform -chdir=infra/responses-api init
terraform -chdir=infra/responses-api apply \
  -var='compartment_id=<compartment-ocid>' \
  -var='profile=DEFAULT' \
  -var='project_display_name=enterprise-ai-demo-responses-api'
```

After apply, export the values required by the backend:

```bash
export OCI_GENAI_REGION="$(terraform -chdir=infra/responses-api output -raw oci_genai_region)"
export OCI_GENAI_PROJECT_ID="<project-ocid-from-provisioning-logs>"
export OCI_GENAI_API_KEY="<api-key-secret>"
```

All new infrastructure required by portal demos should be added as Terraform code under `infra/<demo-id>` and surfaced through outputs instead of being created manually.
